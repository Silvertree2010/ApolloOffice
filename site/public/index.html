01Pipelines

Any start. Any team.
Any route.

Put a pipeline together from blocks in the editor. Click the plus on a step to say what comes next, drag steps to move them. Every worker can run on a different model and a different machine.

  1. 01Press Start

    Run it yourself, whenever you want.

  2. 02On a schedule

    Every day, every hour, any cron time.

  3. 03New issue

    For each new GitHub issue, filtered by label if you like.

  4. 04New pull request

    For each pull request that comes in.

  5. 05Webhook

    Another app calls a link, for example CI or your own scripts.

  6. 06Do something

    A team member gets a task and does it.

  7. 07Check the work

    Someone reviews it. If it is wrong, it goes back to be fixed.

  8. 08Choose a way

    Go different ways depending on the answer.

  9. 09At the same time

    Start several steps together, then wait for all.

  10. 10Ask me first

    The pipeline waits until you say yes.

03Bug-fix team

The first team
comes ready.

One click hires the bug-fix team with its pipeline: from issue to pull request. It does not trust the model. ApolloOffice runs the proof itself: the new test has to fail without the fix and pass with it, and your suite has to stay green. Otherwise no PR opens.

ao-testbed#7 · Fix mean() dividing by len(xs) + 1

# without the fix, on main
$ pytest tests/test_mean.py
FAILED  test_mean   mean([2, 4]) returned 2.0, expected 3
✓ red without the fix

# with the fix
$ pytest tests/test_mean.py
PASSED  test_mean
✓ green with the fix

# whole suite
$ pytest
PASSED
✓ test command still green

→ PR waits for your approval: diff, proof, editable text

04Features

Runs on your machine.
Answers to you.

One binary. Your GitHub, your AI accounts, your Docker. There is no ApolloOffice server in the middle and nothing to sign up for.

⌁

Any provider per worker

Claude Code or Codex with your own login, the Claude, OpenAI or Gemini API, or a local model through Ollama.

▣

Docker isolation

Repository code runs in containers on this computer or on any machine you reach with ssh. The GitHub token stays home.

◷

Costs and budgets

Cost per job, worker and repository, a daily USD budget, and which model gets merged most per dollar.

⚿

Secrets, kept back

Give workers keys for other services. Runs started from GitHub or a webhook never get them.

⌘

API and MCP

Start pipelines, answer approval steps, read jobs, PRs and costs. As a REST API and as MCP tools for Claude Code, Cursor and other agents.

✓

Honest commits

Every commit names the models that wrote it, every PR says it was made with AI. Always on.

06FAQ

Questions.

Does my code leave my computer?

Only to the AI provider you choose for a worker, and to GitHub when a PR opens. With Ollama no code goes to an AI provider at all. ApolloOffice itself sends us nothing.

Does it open PRs without asking?

No. By default every PR waits for your approval with the diff, the proof and an editable text. You can switch single repositories to submit on their own.

What does it cost?

The app is free and open source. You pay your AI provider per use, or nothing extra if you use an existing Claude or ChatGPT subscription through Claude Code or Codex, or a local model. With a daily budget the office pauses until midnight once the limit is reached.

Is it only for bug fixes?

No. The bug-fix team is one ready-made pipeline. Build others for release notes, translations, reports, research, dependency upkeep or backups, with the roles above or your own.

Can it build features too?

Feature mode is off by default. Turned on, Scout and Vet also pick small, clearly specified feature requests, a Planner checks the feature is still missing and Fixer builds it test-first.

Is it stable?

It is in beta. Expect bugs and report them.
